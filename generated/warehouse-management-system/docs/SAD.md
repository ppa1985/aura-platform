## 3. Components

- **UI (`src/app/`)** — server + client React components. Deterministic layout:
  one list + new + detail page per entity.
- **API (`src/app/api/<entity>/`)** — thin Next.js route handlers that validate
  input with Zod and issue parameterized SQL against the app's schema.
- **Data access (`src/lib/db.ts`)** — a single `node-postgres` pool configured
  from `DATABASE_URL`; all queries run inside `SET search_path TO app_warehouse_management_system, public`.
- **AI client (`src/lib/ai.ts`)** — calls the configured
  Ollama endpoint. Enabled because the Blueprint sets `ai_enabled = true`.

## 5. Key cross-cutting decisions

- **Schema-per-app isolation** — no row-level multitenancy; all data lives in
  `app_warehouse_management_system`. Cheap blast-radius containment.
- **Deterministic codegen** — no runtime template injection; the app's files are
  materialized by Aura once and checked in.
- **Thin server, no ORM** — parameterized SQL keeps generated code readable and
  avoids a heavy runtime dependency.
- **Self-healing loop** — Aura runs `tsc --noEmit` on the generated code and
  can patch files via LLM before declaring the app ready.

## 6. Deployment

- **Development**: `npm run dev` on port 3000, with `DATABASE_URL` pointing at
  the Aura Postgres instance.
- **Production**: `docker build` using the generated `Dockerfile`. The platform
  registers the image with Traefik so it is reachable at
  `/generated/warehouse-management-system`.

## 7. Observability & operations

- Logs: stdout; Traefik annotates per-request logs upstream.
- Metrics: not emitted by the generated app (platform concern).
- Backups: owned by the platform's Postgres — per-schema `pg_dump` is supported.
